# バックアップと復旧

PPM の情報は、すべて共有フォルダのファイルです（[進捗はファイルで管理される](../concepts/progress-files.ja.md) を参照）。
現在のバージョンではPPM 自体にバックアップの機能はないので、スタジオのふだんのバックアップに、これらのフォルダを含めてください。

## バックアップの対象

| 対象 | 場所 | 失ったとき |
|---|---|---|
| プロジェクトのファイル | Stuff フォルダの `projects` | 作り直せません。工程の設計をやり直すことになります。 |
| リネームスクリプト、`defaultusersettings.ini` | Stuff フォルダ | 作り直せません。 |
| カットのファイル（キューファイルを含む） | ルートフォルダ | 作り直せません。 |
| 工程グループの所属（`LO.ini` など） | プロジェクト情報フォルダの `progress` | カットが一覧に並ばなくなります。カットを登録し直す必要があります。 |
| 工程ごとのカットの一覧（`LO_details.ini` など） | プロジェクト情報フォルダの `progress_cache` | 工程グループの更新ボタンで、キューファイルから作り直せます。 |
| カット情報とテイクの記録（`c0001.ini` など） | プロジェクト情報フォルダの `scene_info` | 作り直せません。カット情報を付け直し、テイクの数を手で直すことになります。 |
| カットのログ、Google 連携の記録 | ログフォルダ | 作り直せません。 |
| 環境設定（`usersettings.ini`） | 各 PC の `%LOCALAPPDATA%\PPM` | 各スタッフが設定し直せば済みます。 |

- **ルートフォルダ、プロジェクト情報フォルダ、ログフォルダは、同じ時点のものをそろえてバックアップしてください。** 時点がずれたものを戻すと、カットのファイルの状態と、PPM の記録が食い違います。
- バックアップは、PPM を使う人がいない時間（夜間など）に取るのが安全です。

### プロジェクトの設定を変える前に

プロジェクトの設定を大きく変える前には、`projects` フォルダの `.ppmprj` ファイルをコピーしておきます。

- コピーは、`projects` フォルダの **外** に置くか、ppmprj以外の拡張子に変更してください（例：`stuff/projects_backup/sample_project_261030.ppmprj` あるいは `stuff/projects/sample_project.ppmprj_bkup261030` など）。`projects` フォルダの中に`.ppmprj`ファイルを置くと、メイン画面の **プロジェクトID** の一覧に並んでしまいます。
- 新しい設定を試すときは、プロジェクトを別のIDで保存して試す方法もあります（[プロジェクトの保存とテスト](../designing/saving-and-testing.ja.md) を参照）。

## 復旧

### プロジェクトのファイルを戻す

1. 全員に PPM を終了してもらいます（PPM を起動したままの人がプロジェクト設定を保存すると、戻したファイルが上書きされるためです）。
2. コピーしておいた `.ppmprj` ファイルを、`projects` フォルダに元の名前で置きます。
3. PPM を起動して、設定が戻っていることを確かめます。

設定を戻しても、カットのファイルやカット情報は元に戻りません。
戻した設定と、カットのファイルの名前や置き場所が合っているかを確かめてください（[運用中に設計を変えるときの注意](../designing/changing-in-production.ja.md) を参照）。

### 工程ごとのカットの一覧を作り直す

`progress_cache` フォルダのファイルが壊れたり消えたりしたときや、バックアップから戻したときは、メイン画面で、工程グループごとに更新ボタン（回転矢印のアイコン）を押します。
その工程グループに所属しているカットについて、キューファイルを探し直し、一覧を作り直します（[カットがリストに並ぶ条件](../using/scene-list.ja.md) を参照）。

### 1つのカットを前の状態に戻す

アクションを実行した直後なら、**取り消す** ボタンで戻せます（[カットに対する操作](../using/scene-operations.ja.md) を参照）。
**リスト更新** を押した後や、ほかの PC で実行されたアクションは、ファイルを手で直します（[ファイルを直接扱う](../concepts/working-with-files.ja.md) を参照）。
何がいつ行われたかは、カットのログで確かめられます。

## ログから経緯をたどる

カットのログには、そのカットに対して行われた操作が、1行ずつ追記されます。
メイン画面の **ログを見る** ボタンか、ログフォルダの `c0001.md` のようなファイルをテキストエディターで開いて読みます。

```
## カット c0002 のログ

|日時|Workflow|アクション|ユーザ名|
|-------------|----------|----------|---------|
|2026年 10月29日  14時34分32秒|工程の移行|カットを登録|peter|
|2026年 10月29日  14時34分32秒|LO 監督チェック|カットを登録|peter|
|2026年 10月29日  14時35分11秒|カット情報の変更|BG Only : 登録|peter|
|2026年 10月30日  10時12分05秒|LO 監督チェック|承認|paul|
```

### 記録される内容

| Workflow の列 | アクションの列 | 内容 |
|---|---|---|
| 工程の名前 | アクションの名前 | アクションを実行しました。 |
| 工程の名前 | `[失敗] ` ＋アクションの名前 | アクションが途中で失敗しました。失敗する前のステップは実行されたままです。 |
| 工程の名前 | `[取り消し] ` ＋アクションの名前 | アクションを取り消しました。 |
| 工程の名前 | `[取り消し失敗] ` ＋アクションの名前 | 取り消しが途中で失敗しました。 |
| 工程の名前 | `工程内リテイク：〇〇に戻す` | 工程内リテイクで、〇〇の工程に戻しました（[リテイク](../using/retakes.ja.md) を参照）。 |
| 工程の名前 | `カットを登録` | カット登録で、その工程に登録しました。 |
| `工程の移行` | アクションの名前、または `カットを登録` | カットの所属する工程グループが変わりました。 |
| `傍流工程を追加` | アクションの名前 | カットが傍流に追加されました。 |
| `カット情報の変更` | `カット情報の名前 : 登録`、`カット情報の名前 : 解除` | カット情報が付けられたか、外されました。 |

- **ユーザ名** は、Windows のユーザー名です。環境設定の **ユーザー名** ではありません。
- 見出しや日時の書き方、`[失敗]` などの文字は、**操作した人の PPM の言語** で書かれます。英語の PPM で操作した行は、`[FAILED]` や `2026 10/30 10:12:05` のように記録されます。
- ログに残るのは、アクションの名前だけです。どのファイルが動いたかは記録されません。アクションのステップは、プロジェクト設定で確かめてください。失敗したときの **Show Details...** の内容も、ログには残りません。

### Google 連携の記録

Google スプレッドシートへの書き込みと、Google Chat への通知の記録は、ログフォルダの次の場所に残ります。

| 記録 | 場所 |
|---|---|
| スプレッドシートへの書き込み | `google_spreadsheet_cues` フォルダ（[Google スプレッドシート連携](../integrations/google-spreadsheet.ja.md) を参照） |
| Chat への通知 | `google_chat/google_chat.log`（[Google Chat 通知](../integrations/google-chat.ja.md) を参照） |
