# プロジェクトの保存とテスト

## プロジェクトを保存する

プロジェクト設定のダイアログの左下にある **保存する** を押すと、設定がプロジェクトのファイルに保存されます。

- **保存する** を押しても、ダイアログは閉じません。続けて編集できます。
- 保存していない変更があるときは、ダイアログのタイトルの末尾に `*` が付きます。
- 保存していない変更があるまま **閉じる** を押すと、保存するか、変更を破棄するかを選ぶメッセージが表示されます。
- 左下の **プロジェクトID** の欄が空のときは、保存できません。保存しようとすると、プロジェクトIDを入れるよう求めるメッセージが表示されます。
- **プロジェクトID** は、プロジェクトのファイル名です。基本情報の **プロジェクト名**（画面に表示する名前）とは別のものです。
- プロジェクトのファイルに書き込めなかったとき（Stuff フォルダが読み取り専用になっている、など）は、エラーのメッセージが表示されます。このとき、タイトルの `*` は消えず、変更は保存されていない扱いのままです。

### 保存先

プロジェクトは、Stuff フォルダの `projects` フォルダに、`プロジェクトID.ppmprj` という名前で保存されます。

```
Stuff/
└─ projects/
   ├─ sample_project.ppmprj
   └─ my_title.ppmprj
```

プロジェクトIDの欄を書き換えて保存すると、別のプロジェクトとして保存されます。
元のプロジェクトのファイルは、そのまま残ります（[設計の流れと事前準備](overview.ja.md) の「新しいプロジェクトを作る」を参照）。
そのIDのプロジェクトがすでにある場合は、上書きしてよいかを確認するメッセージが表示されます。

### 保存した後

保存してダイアログを閉じると、メイン画面は保存したプロジェクトを読み込み直します。
このとき、すべての工程グループについて、工程グループの更新ボタンと同じ処理（カットのファイルを探し直して、工程ごとのカットの一覧を作り直す処理）が行われます。

ほかの PC の PPM には、すぐには反映されません。
ほかの PC では、PPM を起動し直すか、メイン画面でいったん別のプロジェクトに切り替えてから戻すと、新しい設定が読み込まれます。

> **注意**：プロジェクトのファイルは、最後に保存した内容で丸ごと上書きされます。
> ほかの人が先に保存していた場合は、下の「保存するときの確認」のとおり、メッセージが表示されます。そのまま上書きすると、その人の変更は消えます。
> 設定を編集する人は、1人に決めておくことをおすすめします。

### 保存するときの確認

「100カットごとにまとめる [SEQUENCE]」のオン・オフを変えて保存しようとすると、確認のメッセージが表示されます。
まだ `[SEQUENCE]` を使っている設定（パスマクロ、カットサムネイルのパス、工程グループ、工程）があれば、その一覧も表示されます。
制作の途中で変える場合の注意は、[運用中に設計を変えるときの注意](changing-in-production.ja.md) を参照してください。

この PPM がプロジェクトを読み込んだ後に、ほかの人がプロジェクトのファイルを保存して書き換えていた場合も、保存しようとすると警告のメッセージが表示されます。

- **Save** を押すと、この PPM の内容で上書きします。ほかの人の変更は消えます。
- ほかの人の変更を残したい場合は、**Cancel** を押し、プロジェクト設定を保存せずに閉じます。そして、PPM を起動し直すか、メイン画面でいったん別のプロジェクトに切り替えてから戻して、プロジェクトを読み込み直してから、もう一度編集します。

### バックアップ

設定を大きく変える前には、`projects` フォルダの `.ppmprj` ファイルをコピーしておくと安心です。
元に戻したくなったときは、コピーしておいたファイルを元の名前に戻します。
詳しくは [バックアップと復旧](../administration/backup.ja.md) を参照してください。

## 本番前の確認手順

作ったプロジェクトは、本番のフォルダで使う前に、テスト用のフォルダで一通り動かして確かめます。

### 1. テスト用のプロジェクトを用意する

1. 作ったプロジェクトを開き、プロジェクトIDを `my_title_test` のように変えて保存します。
2. **基本情報** で、ルートフォルダ、進捗情報用フォルダ、履歴のルートフォルダを、テスト用のフォルダに変えて保存します。

テスト用のフォルダには、本番と同じフォルダ構成で、カットフォルダをいくつか用意しておきます。

### 2. 設定の漏れを確かめる

**工程 - フローチャート表示** で、警告のアイコンが付いている工程やつながりがないか確かめます（[工程を設計する](workflows.ja.md) を参照）。
意図して手作業でファイルを置く流れの場合は、警告が付いていても問題ありません。

### 3. テスト用のカットを流す

1. メイン画面で、最初の工程を右クリックし、**この工程から始めるカットを登録する** でテスト用のカットを登録します（[カットの登録](../using/registering-scenes.ja.md) を参照）。
2. 各工程のアクションを、順に実行します。確認画面で、リネーム先やコピー先のファイル名が意図どおりか確かめます。
3. **リスト更新** を押して、カットが次の工程に並ぶか確かめます。
4. **カットフォルダを開く** で、エクスプローラーでもファイルの名前と場所を確かめます。
5. **取り消す** を押して、元に戻るかも確かめます。
6. **ログを見る** で、ログが記録されているか確かめます。

工程グループをまたぐアクション、条件分岐のあるアクション、リテイク、工程内リテイクを使う場合は、それらも一通り試します。
Google スプレッドシート連携を使う場合は、テスト用のスプレッドシートで試します。

カットが思った工程に並ばないときは、[カットがリストに並ぶ条件](../using/scene-list.ja.md) の確かめ方を参照してください。

### 4. 本番に切り替える

テストが終わったら、本番のプロジェクトのフォルダの設定を確かめて、スタッフに使い始めてもらいます。
テスト用のプロジェクトのファイルは、`projects` フォルダから消しておくと、スタッフが間違えて選ぶことを防げます。
